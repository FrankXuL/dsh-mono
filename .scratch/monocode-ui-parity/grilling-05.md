# 票 05 grilling 记录：长期方案决策

按时间顺序记录每个决策与理由，供写方案时引用。

| # | 问题 | 决定 | 关键理由 |
|---|---|---|---|
| 1 | 插件定位 | **A 补充件** | 新增 `main` key，宿主 UI 一行不动。这是唯一不与宿主打架的形态；探针已证明可与 `conversation`/`plugins` 并存。B（替代件）正是 multipane 被诟病的 `priority:-1` 抢占。 |
| 2 | 包名 | **dsh-mono** | 用户指定。全仓 `monob` 已清零，隔离 profile 回归通过。 |
| 3 | 标签模型 | **A 每栏标签条** | 一个标签 = 一条会话。比"只有栏"多一层状态，但保住空间记忆与"开着不看"的能力。 |
| 4 | preview 临时态 | **A 做** | 否则点侧栏会以最快速度堆满标签。成本 S 级：一个布尔 + 一次替换 + 双击转正。 |
| 5 | 分栏模型 | **A 嵌套二分树** | 支持任意切分（2×2、1+3 等）。单层网格够用但上限明显。 |
| 6 | 代码来源 | **B 从零写** | 风格统一优先。monocode 仅作思路参考，不复制代码（MIT 本可复用，但用户要求自写）。代价：边界规则需自行推演。 |

## 由此产生的已知代价

- 嵌套树的边界规则（同轴归组、父节点塌缩、8% 最小尺寸、垂直边嵌套而非替换）需自己推演，不能照抄。
- 工作量比"搬运"方案多约 3~5 天。
